# Frontend motion audit and selected subtraction

Existing audit and planning owners survey motion read-only, present vetted choices, and obtain explicit selection before the implementation owner changes source. Main sessions and delegated explorers reach the same conditional guidance. Selected subtraction preserves functional lifecycle and useful unselected motion through existing motion review and Verify.

## Sub-features

- `motion-audit-main`: a fresh existing grill or planning task vets and prioritizes motion findings without changing source.
- `motion-audit-worker`: an actual read-only vstack-explorer reaches the audit and opportunity references and contributes findings for coordinator vetting.
- `motion-audit-selection`: source hashes remain unchanged until an explicit selection arrives through the existing UI or user-turn interface.
- `motion-subtraction`: the implementation owner removes only selected motion, including hidden initial styles and obsolete callback waits, while preserving focus and useful motion.
- `motion-subtraction-review`: the existing review owner assesses the real resulting behavior with applicable evidence rather than a blanket property ban.

## How to get to it (user POV)

- Start an existing grill or planning task to audit frontend motion. Good-css conditionally reaches improve-animations, its audit and selected-requirements companions, and the opportunity and subtraction guidance where relevant.
- Delegate a source audit to the existing vstack-explorer. Its frontend pointer reaches the same references even though automatic Brief selection remains principle-only.
- Select a bounded finding in the current owner's Flow question round. The existing implementation owner carries that scope through ordinary review and Verify. No separate UI command, upstream execute dispatch, plan directory, or animation-status subsystem is involved.

## Driving it with native omp, the browser, and public CLIs

Preconditions:

- Follow [frontend guidance](frontend-guidance.md) for Doctor, fresh native sessions, caller Session model and thinking, complete-plugin loading, isolated discovery, actual transcript capture, public maintenance commands, packaging, and final gates.
- Keep every fixture and before snapshot under the proof run. No new package is needed for a vanilla HTML/CSS/JS application. Record its actual dependency declarations and browser capabilities.
- Give each diagnostic app its own fixture Git project and fixture vstack root, not the production project's root or ticket aliases. Use an explicit isolated Flow `--home` under the proof run on every diagnostic authoring command, with the native process's own session and agent. Pass that isolation to delegated briefs. Keep real model credentials available through the native launcher, but never use production Flow bindings for test Results, questions, selections, or Stage completion. Inspect actual calls and receipts before accepting the trace. A model-written test record in a production Flow is a retained side effect, not a production decision; stop further writes and repair isolation without deleting the record.
- Every browser open, including diagnostics and delegated calls, explicitly passes `app: { tern: false }`. Record the returned backend and engine, inspect actual tool calls, retain full-resolution lossless WebP and ARIA, and close only owned resources.

### Establish the failing behavior

1. Use a keyboard-first dispatch fixture with Commands, a visible close-count status, an occasional Delivery preview, a stable Queue table, and a rare completion status. State frequency and lifecycle expectations in the fixture spec.
2. Make Commands start at opacity zero and an 80px offset with a 650ms ease-in entry. Focus its input only on `animationend`. Make exit wait 650ms before unmount, count update, and focus restoration. Leave that motion unconditional so reduced motion also exposes the problem.
3. Keep an independent 180ms ease-out clip-path preview reveal guarded by no-preference. Do not select it for deletion. A dependency-free fixture validates native CSS and DOM behavior, not Motion or component-library APIs.
4. Through real keyboard controls, observe entry opacity, transform, input focus, and exit mounted state/count/focus. Retain the false immediate-visibility and immediate-unmount signals. Capture source hashes and a full-resolution screenshot. Establish no-preference or reduced motion with `matchMedia`, not an assumed wrapper default.
5. Before plugin edits, run a fresh native read-only audit and retain its actual findings. A baseline model may independently find the defects. Missing new guidance is source-coverage before/after evidence, not proof that the old pack could not diagnose them.

### Audit and select through existing ownership

1. After plugin edits, drive a new native `/skill:grill-with-docs` or existing planning task on an identical source copy. Request read-only motion surveying, vetted priorities, separate additive opportunities, and rejected candidates. Require a stop before selection. Keep the native entry expansion, actual reads, findings, and source hashes.
2. In a separate fresh native run, use the existing single-explorer contract for a delegated audit. Pass the allowed tree, vstack root, Scratch, browser evidence, and read-only requirement. Leave UI Utility skill names out of its Brief. Inspect the actual explorer history and contribution. The coordinator must re-read cited locations before presenting priorities.
3. Both paths should reach improve-animations, AUDIT.md, and the relevant opportunity/subtraction guidance. Distinguish existing-motion defects, useful existing motion, additive proposals, and rejected candidates. The Queue and keyboard Commands are unsuitable additive candidates. Rare completion feedback can be an optional proposal, not an invented defect.
4. Compare every application source hash with the before snapshot. A report written under Scratch is permitted. No source, manifest, lockfile, or other application change is permitted before selection.
5. Publish findings through the current owner in a production Flow. Follow flow-page's "Every ask in a Flow" contract for selection, including complete publication, current-content checks when serving, ordinary `ask`, and separate raw-response recording. For a diagnostic harness, retain the deliberate choice sent through the existing UI or later native user turn in its isolated fixture Flow. Label it a fixture selection, not an actual user's choice. A default recommendation, timeout, cancelled picker, or headless response is never selection. If using native RPC without a picker, stop the audit, then resume the saved session with a separate explicit selection turn.
6. Select only Commands entry/exit subtraction and required lifecycle cleanup. Do not select optional completion motion, preview retuning, new dependencies, or package removal. Record the exact turn and source state at that boundary.

### Implement and observe the selected result

1. Through the existing implementation owner, remove Commands entry/exit motion and obsolete hidden initial styles. Move input focus to mount and close-count update, unmount, and focus restoration to immediate close. Preserve exactly-once semantics and remove obsolete waits rather than retaining a 650ms pause without visible motion.
2. Reuse actual source excerpts and the existing selected-requirements companion in the owner's hand-off. No independent plan-status file or executor is needed. Inspect imports and dependencies before cleanup. An unused library may be proposed for removal, not uninstalled without separate approval.
3. Observe Control+K, immediate visible input and focus, Escape, immediate unmount and count update, repeated close, and close/reopen within the old duration. After more than 650ms, the new panel must remain mounted and focused without a stale callback. Repeat under verified reduced motion.
4. Toggle the preserved preview under no-preference and capture its actual intermediate clip and active playback. Under reduced motion, verify its functional state is immediate and nonmoving. Keep its useful effect and the unselected completion behavior unchanged. Do not claim an exit animation or smooth reversal if this fixture only has an entry reveal.
5. Give the resulting source and real browser observations to the existing motion-review path. Require review-animations and its standards, retained blocking authority, locations and evidence, and a browser-qualified explanation of the kept clip-path. Missing trace-based cost or other-engine proof remains unassessed.
6. Retain exact native tool calls, coordinator and child histories, explicit selection provenance, selected edits, browser state, review, dependency facts, and teardown. Synthetic DOM/timer doubles are not browser proof and are unnecessary for this recipe.

Do not rerun unchanged stochastic corpora to chase unrelated failures.

## Gotchas

- A read-only report, publication, or top-ranked recommendation authorizes no edits. Preserve the actual explicit fixture selection as distinct evidence.
- Removing only CSS can strand opacity zero, focus callbacks, or exit timers. Assert lifecycle and visibility through real controls.
- A native model can identify the problem before these Addons ship. Report actual source and behavior, not an unsupported causal score.
- Catalog selection is not delegated activation. Inspect the explorer's real conditional reads and contribution.
- Browser support and interpolation do not prove compositing, low frame cost, physical touch, Safari, or Firefox. Keep claims within the observed engine and fixture.
- Parent Flow publication and final integrated verification remain parent-owned. This recipe exercises the three-skill audit path, not the behavioral coverage of the other shipped guidance.
