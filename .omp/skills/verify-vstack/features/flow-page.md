# Flow page

The flow-page script takes typed contributions for one bound Stage, assigns ids, Q numbers, option letters, Stage labels, and links, and commits them to the Flow. The Local Flow host serves the prebuilt Nuxt reader. A 44 px sticky bar shows the project, Flow, Focused Stage, and open question chips. Stages opens the Map panel and Jump opens the reading index. Each Stage lists its content in first-publication order. Answers and Result revisions stay in place with history. Unprovable historical order stays behind a retained-order boundary at the top of its Stage. A bare URL opens Overview with open decisions grouped by Stage. Progress, visit changes, All Stages, and Topics follow as closed rows. The footer holds the revision and the theme control, which switches between Catppuccin Mocha and Latte and defaults to the system preference.

## Sub-features

- `flow-open`: `open` starts a Flow with a Stage for any skill name, or adds a Stage to an existing Flow, and binds the calling session's agent.
- `flow-bind`: a session writes only through its own binding or an explicit `--flow` and `--stage`. `bind` and `show` create no Stage and no revision.
- `flow-submit`: a contribution returns assigned refs, the numbered label-only `ask` payload, the revision, and `live`, with no content echoed and no file path.
- `flow-refuse`: an unsupported version, unknown kind or field, missing link, `again` cycle, or invalid transition is refused, naming the item, and commits no Flow content. On-demand host lifecycle metadata may still change.
- `flow-reader-needs`: every fresh or re-asked question declares nonempty `{ need, kind }` reader needs and satisfies each non-prose kind on that question or its options. Missing needs, unrequested kinds, and misplaced option previews refuse the whole contribution. Old stored records remain readable without invented needs.
- `flow-decision-brief`: a new round has a shared Now line and each question has a Decision brief. An incomplete or conflicting brief refuses the round. Stored and migrated questions keep their descriptions and choices without an invented brief.
- `flow-links`: questions link to Result entries and Topic notes, and the page shows the backlinks. A re-ask links to its earlier ask, and a decided question links to its summary.
- `flow-answers`: an answer keeps the raw `ask` response apart from the agent's reading. Only an explicit pick or a resolved reading counts as the user's answer, and the page shows a resolved reading's basis with no option marked picked. Question-notes, concerns, ambiguous notes, timeouts, cancellations, empty and headless responses stay open as non-consent.
- `flow-lifecycle`: finishing a Stage retires each unresolved question with a reason. A later Stage opened with `--parent` asks a retired question again with `again`, and the two questions link to each other. A second answer to one question is refused. The close lists every decision with its provenance and every Assumed pick no question reopened.
- `flow-view`: reading blocks carry skill-derived Stage labels with ticket ids, a card's Evidence opens with one click, and a 360px pane has no horizontal overflow.
- `flow-concurrent`: callers bound to two ticket Stages of one Flow submit and add aliases at the same time, and every contribution and alias lands once. A repeat of a Stage's latest contribution prints its first receipt with `repeated: true`. A `revise` of one entry with an old `base` after another revise of it is refused as a conflict.
- `flow-identity`: `find` and `--flow` take qualified aliases (`spec:`, `ticket:`, `branch:`, `run:`, `folder:`, `slug:`) and refuse a missing or ambiguous one. `move --to <key>` keeps the id, bindings, anchors, and the old folder key, and a taken key or a failed rename leaves the Flow where it was. Another project cannot find or write the Flow; a worktree of the same project can.
- `flow-unavailable`: when the host cannot serve (a taken port, an incompatible running host, or an unbuilt reader), the receipt has the new `revision` and `live.state: "unavailable"` with the observed `error`. The content is committed, stderr says so, and fixing the cause then running `bound` or `show` serves it without resubmitting.
- `flow-document`: a `document` Result shows its sections in order, numbered citations that link both ways, code with its whitespace, figures, limitations, and sources.
- `flow-attach`: `attachment` items of every type keep their caption, origin, captured revision, and availability. Captured files are stored in the Flow by sha256 and shown from there. A path outside the project and its Scratch dir, a symlink out of them, an image that is not an image, an unsafe SVG, and a link with an unsafe scheme are refused.
- `flow-revision`: a Result keeps the content and assets it captured after its sources change. `revises` publishes the next revision, with the canonical file's new sha256, and the earlier revision stays readable.
- `flow-progress`: `task`, `blocker`, `end-state`, `pr`, and `check` items put progress on the Overview's strip. A task changes state through a focused update with no resend. Skipped and inapplicable tasks are not left work. The Flow reads complete only when no task or blocker is open and a delivery reached its requested End state. A finished Stage, a merged PR, and a passed check are each their own line and complete nothing.
- `flow-retention`: `close` closes a Flow whose Stages are all finished, and `reopen` continues it with a new Stage. The cleanup script never lists or deletes an open Flow. It lists a closed Flow only after 15 days from close, or the requested age if longer, whatever its file times or page reads. An expired Flow's id is refused with a report rather than started again.
- `flow-demo`: a `prototype` Result is a declarative state demo. It has states, a start, actions with transitions, bounded conditions, typed values, and Reset. The page runs it in the browser. Its state and a video's playback position stay in `localStorage`, survive live updates, and never change the Flow's revision. A condition or change written as code, a type mismatch, an unknown name, or an unreachable state is refused.
- `flow-comparison`: a `comparison` Result shows its verdict first, linked to the chosen alternative, then each criterion against each named alternative with that side's finding and evidence, a gap shown as not assessed, and each side's own attachments. A single alternative, an unknown alternative or criterion, a repeated pair, and a verdict that does not fit its outcome are refused.
- `flow-metrics`: a `metrics` Result shows its workload, environment, and reported outcome, and per measurement a table of each series' value with its unit, samples, uncertainty, and change from the baseline, with a bar on one shared scale beside each measured value. A missing value shows its reason with no number and no bar; a measured zero shows `0` and a zero-length bar. A value given as a string, two baselines, and an inverted range are refused.
- `flow-host`: concurrent commands start one detached host at a stable loopback URL. The generation entry starts the shipped Nitro Bun server and its separate artifact viewer listener. Restart restores stored Flows and their URLs. An open page or publication prevents idle shutdown. An installed supervisor swaps complete generations without changing the URL or credentials and keeps the last good generation after a failed candidate. Isolated development hosts keep their startup bytes until their owner stops them. A taken port, incompatible isolated host, or missing build reports `unavailable`, and the content stays committed.
- `flow-live`: an open live page receives answers, Results, task changes, and new Stages without a reload, keeping its reading stop, fragment, reading position, focus, and open evidence disclosures.
- `flow-access`: scoped read links, Host and Origin checks, and registered captured assets guard the HTTP reader. Read links cannot author, stop the host, run commands, mutate trackers, or merge.
- `flow-migrate`: a structured historical Grilling page becomes a Flow without changing its old folder. Record ids, questions, answers, Q numbers, round times, figures, Topics, sources, and fragment anchors survive. Reports become Results. A handwritten page stays untouched.
- `flow-code`: Code/diff Results show syntax-highlighted excerpts and unified diffs, preserve significant whitespace, and show file, revision, and known source lines. A diff has separate old and new line numbers and linked hunks.
- `flow-timeline`: Timeline Results preserve the supplied event order, known times, explicit outcomes, and evidence attached to the event it proves. Missing times stay unknown.
- `flow-artifact`: a prototype Result names an HTML bundle, local app route, or terminal artifact. Captured bundles execute on a separate read-only viewer origin, local routes stay on their own origin, and missing runtimes show launch instructions with an unavailable state.
- `flow-nav`: the 44 px bar keeps identity, the current question, and navigation controls in one row. Overflow counts open Jump or Stages. `m` opens the Map on Stages, and `g` opens the reading index. In the Map, `h` and `l` switch tabs, `j` and `k` select items, and Enter follows the item or opens its group. With both panels closed, `j` and `k` set fragments and focus at reading stops and `h` and `l` travel between views. `n` cycles open questions in the Focused Stage or uses Flow-wide order from Overview and Topics. Editable targets, media controls, and modifier keys ignore these shortcuts.
- `flow-session`: each session and agent restores its own binding and hidden authoring identity. Completed replies, blockers, follow-ups, and live failures add no automatic Flow message. Persisted historical Flow cards stay out of ordinary-turn model context. A native `ask` through `--rpc-ui` returns labels and custom words that normalize into Flow answers.
- `flow-questions`: complete CLI publication precedes ordinary `ask` with receipt identities, and observed answers are recorded separately. In a bound main-agent interactive TUI, a UI-only Flow panel above the composer shows the clickable Flow URL while the picker is open. The picker opens at once, and the panel goes away when it returns. Every call and retry gets a fresh panel. An unavailable host shows its error in the panel and still allows questions; turn abort closes the picker and the panel. Ratchet's actual `r.approve()` path gets the same panel through `ui.askDialog`, with no panel for reused approval.
- `flow-questions-guard`: a bound main-agent TUI refuses an ask with controls that do not name askable questions in its Stage. A refusal opens neither the picker nor the Flow panel.
- `flow-enrollment`: an ordinary description-selected explanation stays in chat without a binding; a fresh typed explanation enters a Flow and publishes a Document. Neither result-only completion gets a Flow link or automatic card.
- `flow-quiz`: structured choice, text, and numeric quizzes give immediate feedback and explanations. Attempts and completion persist separately from authored work, resume across host restarts, and synchronize browser-local offline attempts idempotently.
- `flow-review`: a review Result opens with one summary table linked to each authoritative finding's impact, action, and evidence card. All three axes retain their explicit findings, clean, skipped, unavailable, or blocked outcomes, and focused corrections update the table.
- `flow-observations`: read-only git, Code host, and CI adapters update the open strip with source and time, without changing authored PRs, checks, End state, or Flow closure. Separate project configuration selects Code host and CI independently.
- `flow-t4`: the combined-product proof of spec #267 T4 on one Flow: live updates and reading state, every navigation key, every Result kind at 1280 and 360 px in both themes, review outcomes, Quiz persistence and offline sync, demos, isolated artifacts and absent runtimes, observations, and host unavailability.
- `flow-diagram-reading`: source-based and historical Pele diagrams retain their intrinsic label size. Wide drawings scroll within a focusable figure, not the page. Arrow keys pan the focused figure without changing the reading stop; theme changes preserve its drawing and stored bytes.
- `flow-finished-reader`: typed-table sorting, filters, and stable row links; line, scatter, and histogram Metrics charts; numbered Document steps; and revision-bound Reader comments work together at 1280 and 360px in Latte and Mocha under the unchanged host CSP.
- `flow-storage`: per-project SQLite preserves every authoring contract, imports existing JSON independently, and keeps old SQLite generations working after additive migrations.
- `flow-storage-cutover`: the first update stops a JSON-only normal host before import; an old supervisor already serving a SQLite worker is retained, and isolated hosts are not stopped automatically.
- `flow-ssr`: the capability URL's first HTML response contains its Stage titles and questions before scripts run. Per-response script hashes preserve the strict CSP. The page hydrates without content mismatch and keeps live updates, reading state, drafts across generation reload, and browser-drawn diagrams.

## How to get to it (user POV)

- A skill runs `bun "$(realpath skill://flow-page/scripts/flow-page.ts)" open|bind|submit|validate|catalog|describe|alias|close|reopen|find|move|show|migrate ...`. `bound` looks up only the current session and agent, without creating a Flow.
- Result-only replies and completion summaries have no Flow link or path reminder. The extension supplies hidden session and agent authoring context without an automatic post-reply message.
- For each question round, submit the complete contribution through the CLI and call ordinary `ask` under flow-page's "Every ask in a Flow" contract. Code looks up the current session and agent's binding and shows the Flow panel above the composer while the picker is open. No assistant link text or URL in the picker payload is needed. Record the actual response through a separate CLI contribution. Ratchet keeps its native approval gate with the same panel beside it. RPC, ACP, print, unbound sessions, and subagents get no panel.

## Gotchas

- Without `--session` and outside an omp session, `open` still creates the Flow but binds nothing, and later `submit` needs `--flow` and `--stage`.
- The cleanup script reads the real time unless given `--now`. Use `--now` for retention proof; never set the system clock.
- The Flow lands under the repo key of the current directory. Run from the checkout, or the Flow goes under `_global`.
- A live `http://127.0.0.1` page receives committed updates itself. Do not reload during `flow-live`, or the proof no longer exercises live reading.
- Full-page screenshots after scrolling can show a sticky element midway down. Scroll to the top before a full-page capture.
- A persistent shell that hashed `bun` keeps running that path after `PATH` changes. Run `hash -r` after pinning Bun.
- `tab.goto` to the same URL with a different fragment does not reload the page, so it keeps the old reader script. Use `tab.reload()` after a reader rebuild, and `host stop` first, since the running host serves the bytes it loaded at startup.
- Repeating a Stage's latest contribution returns its first receipt with `repeated: true` and changes nothing. Change the content for each live update.
