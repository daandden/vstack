5. Same-purpose overlaps under different names

5a. Review: matt code-review vs pstack interrogate (+ reflect) suggested: merge

matt code-review: two-axis review (Standards vs Spec) of the three-dot diff since a fixed point; parallel Standards + Spec workers with <400-word briefs; Spec skipped when absent; aggregate verbatim, never merge/rerank; one-line per-axis summary. pstack interrogate: N-model adversarial review + lead-judgment buckets (see 4.4). pstack reflect additionally mines transcripts into skill edits (judgment/tooling/divergent reviewers + synthesizer, structural-enforcement check, explicit user approval before applying).

Suggested rule: merge — matt’s axes, pstack’s panel. Keep the two-axis frame (the Standards/Spec separation is load-bearing for the vstack tracker workflow) and run each axis through the multi-model panel + synthesis + lead-judgment buckets. Import reflect’s approval gate verbatim if any reflection loop ships (skill edits affect every future agent: never auto-apply). OMP: two reviewer roles × panel = distinct OMP agent identities.

5b. Investigation: matt research vs pstack how / why / investigation playbook suggested: keep all three, route by question

matt research: one background researcher against high-trust primary sources → single cited Markdown file. pstack how: codebase architecture explainer (simple: 1 explainer; complex: 2–4 explorers + synthesizer; readonly true; fixed output sections). pstack why: motive investigator across 7 evidence categories (source control always + tracker/docs/chat/observability/errors/analytics via MCP), one investigator per MCP, agent mode (readonly false preserves MCP), synthesizer with epistemics confidence tiers; null results are findings; output keeps What-We-Found vs Inference vs Don’t-Know separated. The investigation playbook composes how+why into a read-only cited answer (no prototype/code by default).

Suggested rule: keep, route by question. Outside-the-repo question → matt research. How-does-it-work / where-should-it-live → how. Why-is-it-shaped-this-way → why (preserve its confidence language; teach already mandates this). Do not collapse them: their evidence contracts differ. OMP: why/reflect’s readonly=false exists only to preserve MCP — map to OMP tool/policy scoping, not a boolean.

5c. Bug work: matt diagnosing-bugs vs pstack bug-fix playbook (+ blast-radius, forensics) suggested: merge

matt diagnosing-bugs: 6-phase discipline — tight red-capable loop first (10 loop shapes incl. HITL script; tighten for speed/signal/determinism), reproduce + minimise to load-bearing elements, 3–5 ranked falsifiable hypotheses shown to the user, instrument (debugger > targeted tagged logs; perf branch measures first), fix + regression test at a correct seam (missing seam is itself the finding), cleanup (re-run loop, tagged-log grep, hypothesis in commit message). No subagents. pstack bug-fix playbook: parent reproduces; how+why fanout; code-model fix delegate (Grok default); parent replays; cheap-path tdd. blast-radius: find the one safety fact and prove it by running code (said-so → line → walked → ran → reproduced ladder); big changes go to arena.

Suggested rule: merge — matt owns the loop, pstack owns the fanout and the proof. Keep the tight-loop-first discipline, minimisation, and falsifiable-hypothesis checkpoint. Import the parallel how+why investigation fanout and the blast-radius safety-fact proof ladder. Keep pstack’s cheap-path tdd link (see 4.1).
