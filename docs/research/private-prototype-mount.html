vstack · wayfinder ticket #54 · grilling rounds 1–2

Where does a Private-mode UI prototype live when it has to mount in an app route?

In Private mode, every prototype is supposed to stay untracked under <git-common-dir>/vstack/artifacts/<topic>/ and never be committed. Matt's UI branch, though, mounts the variants inside an existing page (sub-shape A), so part of the prototype has to sit in the app's source tree. Each section below covers one question from this round.

What's already established

info/exclude doesn't cover tracked edits

Tested in a scratch repo: a new file listed in .git/info/exclude stays hidden, but an edit to the tracked route file still gets staged.

$ git add -A && git status --short
M  route.tsx      ← staged

A detached worktree stays off every branch

git worktree add --detach worked. Its edits never showed up in the main checkout's status, and they belong to no branch, so there's nothing to push.

A worktree under .git loses hot reload

Vite always adds **/.git/** to its watcher's ignore list (watch.ts). A dev server running inside .git/vstack/… therefore never sees edits.

Q1Where the mounted prototype runs

This is the main decision. The rest of the mechanism follows from it: what keeps the prototype out of commits, what setup it needs, and what cleanup has to undo.

Recommended: a detached worktree outside .git

Nothing in the main checkout changes. The prototype exists only in the detached worktree, which sits on no branch, so there's nothing to commit and nothing to push.

Contrast: edit the main checkout and clean up afterwards

The scratch-repo test reproduced exactly this. Cleanup also has to restore settings.tsx to its exact earlier state, including any edits the user made in the meantime.

Recommendation: detached worktree outside .git. It's the only option where "never committed" holds by construction rather than by the agent being careful. The setup cost buys that guarantee. Where exactly the worktree lives, how deps get in, and which port it uses are round-2 questions if you pick this.

Note on ADR 0007: it rejected git worktree add, but for isolated subagents, which are short-lived and where APFS clone speed matters. A prototype mount has to outlive the session so the user can flip variants, and omp's isolated workspace doesn't. So this doesn't conflict with ADR 0007.

Q3How long the mount stays up, and when it's cleaned up

Rule 7 has the agent observe each variant before handover. After that, Matt's UI.md says the user flips through variants "whenever they get to it", which can be days and several sessions later.

With A, the user can open the URL any time before the verdict. With B, nothing stale is left behind, but every look costs a rebuild, and that needs Q4's capture to exist up front.

Recommendation: A. The session that records the verdict cleans up. Until then, the reply's throwaway notice gives the worktree path and the exact git worktree remove command, so an abandoned mount is easy to find (it also shows up in git worktree list).

Q4What is saved as the primary source

In Standard mode, Matt keeps all the variants on a throwaway branch. In Private mode there's no branch, and the #44 amendment says the issue gets only the verdict. Without a capture step, the variant code disappears with the worktree.

The capture is enough to rebuild the mount later: check out the base SHA, apply the diff, and copy the variant files back in.

Recommendation: save the variant files and the mount diff in artifacts. This keeps Matt's "the prototype is a primary source" rule in Private mode, and Q3's option B depends on it.

Q5Where the winner gets folded in

Matt's step 6 rewrites the winning variant properly in the real code. Private mode keeps vstack artifacts untracked; it doesn't apply to product code.

A matches Matt's step 6 in both modes. B separates "decide" from "build", but it changes what prototype does only in Private mode.

Recommendation: A, unchanged from Matt. The winner is rewritten in the main checkout as ordinary tracked product code. Only the prototype stays untracked.

Round 2: running the prototype worktree

Settled in round 1: a detached worktree outside .git; the rule covers any prototype that can't run on its own from artifacts; the mount stays up until the verdict; variant files and the mount diff are captured in artifacts; the winner is folded into the main checkout as normal product work. Q10Dev server: port and lifetime

Recommended: pick a free port and pass it explicitly (--port / PORT). The server runs as an omp service for the session, and the reply prints the one command that restarts it. No process is left running for days.

Q11When the capture is written

Round 1 put the capture "before cleanup". If the worktree is deleted by hand, or the verdict never comes, nothing is saved. Writing it at handover as well (the first dot above) makes the artifacts dir the primary source from that point on.

Recommendation: capture at handover, refresh at the verdict, then clean up.

Q12ADR and glossary

Every choice here lives in prototype's skill text and is cheap to reverse. That fails domain-modeling's "hard to reverse" test, the same reasoning as #44's no-ADR call. "Prototype worktree" is an implementation detail, not a domain term.

Recommendation: no ADR and no new CONTEXT.md term. The decision lives in this ticket's resolution and in prototype's contract.
