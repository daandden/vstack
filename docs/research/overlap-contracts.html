Rule · ADR 0004 + Fan-out guardrail

Every Fan-out step is one Fan-out block

A block has three parts: a gate line citing the shared rubric, one tasks[] batch, and the inline fallback. The judge picks fan-out or inline, and the user's words override it. One subagent on its own is not Fan-out and runs as written.

Q3Bug material: side file or inline (explained again)

The mechanism. When a skill runs, omp loads its SKILL.md into the agent's context every time. Other files in the skill folder are loaded only when SKILL.md points at them and the agent decides it needs them. tdd/BUG-FIX.md (new, ~35 lines)

# Fixing a bug test-first

1. Understand the bug: intended vs current behavior,
   the smallest observable repro.
2. Pick the narrowest check at an agreed seam.
3. Write the failing test first.
4. Run it. Confirm it fails for the intended reason;
   if not, fix the test or repro before touching code.
5. Make the smallest fix that keeps nearby contracts.
6. Rerun it and see it pass.

## No practical failing test
Use a script, repro command, or browser check only at
a seam the user agreed. Nobody to agree it: stop the
slice and report the missing red evidence and why.

## Guardrails
- Keep the test focused on this bug.
- Flaky bug: make the test deterministic.
- Land the focused test before sibling coverage.

## Reply
- The failing-before check and the failure it gave.
- The passing-after run.
- Or: why red evidence is missing.

Q13Final Safety trigger list, and who applies it

Draft wording. The axis runs when:

  1. the user asks for safety or blast radius; or the diff changes something that code outside the diff depends on:
  2. Public interface: an exported symbol, endpoint, CLI command or flag, or event is changed or removed.
  3. Persisted or wire data: a schema, migration, serialized format, stored key, or API payload.
  4. Configuration: a config key, env var, feature flag, or default.
  5. Dependencies: a dependency is added, removed, or bumped; a lockfile changes; a local patch is added or changed.
  6. Lifecycle or ordering: init or teardown order, async timing, concurrency, or cache invalidation.

"Outside the diff" replaces "across a boundary", so code-review doesn't take on a word codebase-design bans.
