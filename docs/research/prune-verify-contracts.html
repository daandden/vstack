prune-comments and the app-verification skills

Explainer for Specify the vstack contracts of prune-comments and the app-verification skills, part of the map vstack: Matt Pocock skills plus pstack enhancements for omp. It covers three pstack items. no-comments becomes prune-comments, which spawns vstack-comment-critic. create-verification-skill becomes setup-app-verification, which generates a project verify-<app> skill. maintain-verification-skill becomes maintain-app-verification, which keeps that skill honest. Verify skill: where and how it is found

Q1Where the verify skill lives in Private mode

Standard mode is settled: .omp/skills/verify-<app>/, tracked in the repo. In Private mode, vstack artifacts are untracked under <common>/vstack/. The verify skill is long-lived tooling made of a SKILL.md, a feature map, and helper scripts. omp facts:

  • Native discovery scans only <ancestor>/.omp/skills/*/SKILL.md from the cwd up to the repo root (docs/config-usage.md:283). A dir under .git/ is never discovered.
  • A symlinked skill dir is admitted (discovery/helpers.ts:514: isDirectory() || isSymbolicLink()).
  • Skills are discovered when the session starts, so a link created mid-session shows up in the next session.
  • .git/info/exclude lives in the common dir, so every worktree shares it, and it never touches tracked ignore files.

Option A. The live-proof block's “list the verify skills” step also globs <vstack root>/skills/verify-*/ and reads SKILL.md by path. omp never lists it in the prompt.

Q2Where proof evidence and run notes go

pstack only says evidence survives cleanup “in a location the skill names”, and that maintain's run notes are scratch that is never committed. Both have to outlive an isolated clone, because a ship verifier's clone is discarded.

Option A. Option B writes the same files under <vstack root>/artifacts/verify-<app>/. That location persists, but in Standard mode it's the repo root, so it needs an ignore entry or it shows in git status.

Recommendation: A, $TMPDIR. It's never committed in either mode, outlives clones, and needs no ignore rules. Evidence is per-run proof, not a durable artifact.

Q4Critic spawn fallback, and what a caller does on failure

The single-spawn template needs an “if it cannot be spawned” clause. pstack's no-comments also fails after a second rejected critic report. The critic's rules live in the agent body, not in the skill (“Do not restate its rules”), and the skill exists to get a fresh context.

Option A. The coral path is the failure route: prune-comments stops, and the caller keeps going and lists it as open in the reply. Option B swaps “stop” for “do it yourself”. Option C turns the coral arrow into “caller stops the chain”.

1. **Spawn** one `vstack-comment-critic` via `task` (`agent: "vstack-comment-critic"`): the scope,
   the user's override words, the vstack root. Wait for its result. If it cannot be spawned,
   **stop**: the critique needs a fresh context; report prune-comments as not run.

Recommendation: A. Comment cleanup is quality work, not a gate on correctness, so a stuck critic shouldn't block a PR. In practice the spawn only fails on machines with a depth cap, because every caller runs in the main session.

Q1′Private mode: vstack root, in-checkout + exclude, or both

Facts checked against the omp source and a throwaway repo:

  • omp does discover an excluded .omp/skills/verify-* dir. The native scan is a plain readdir with no gitignore filter (discovery/helpers.ts:465, called from builtin.ts:303).
  • .git/info/exclude resolves to the common dir from every worktree, so one entry covers them all.
  • git worktree add creates a worktree without the skill, because untracked files don't carry over. /wt and isolated tasks clone the whole tree, so they get a copy, and edits to that copy never merge back (ignored files are left out of the merge).
  • git clean -fdx deletes .omp/, and with it the feature map and the helpers. git clean -fd keeps it.
  • The glossary defines Private mode as artifacts “kept untracked under the git common directory and shared by all of the project's worktrees”. ADR 0006 puts everything under .git/vstack/.

Option E is your proposal plus a single home. omp discovers the link, every edit lands in one copy, and git clean -fdx removes only the link. In a checkout with no link, the live-proof step creates it and reads SKILL.md by path for that session.
