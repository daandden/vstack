# Flow page output contracts

Research date: 2026-10-27. This is a source inventory and coverage reference for the Flow page design, not an implementation specification.

Status: vstack 7.0.0 ships the design (spec #267, [ADR 0040](../adr/0040-structured-flow-data-drives-server-rendered-pages.md)). Every output family below now publishes through flow-page. The shipped contract settles the gaps listed at the end: typed attachments; declarative demos, quizzes, and isolated runnable artifacts, with diagram motion left out of scope; explicit review and setup outcomes; captured revisions with canonical links and lifecycle retention; a Stage-only `t` tree; and Stage labels for any skill name. The inventory still describes the sources as they were on the research date, and it remains the coverage checklist. Links into the removed grilling-page skill point at commit 7692b30, the last one that had it.

## Scope and completeness

The shipped catalog contains **76 skills: 25 Matt skills, 16 Utility skills, and 35 Addons**. The Addons comprise 22 principles and 13 other Addons. The extension registers **one user Command**, `/vstack-clean`, and two agent-facing Addon-selection tools. Every skill appears in the inventory below. Supporting agent and script outputs are accounted for separately, not counted as additional skills.

These are catalog classes, not workflow classes. A Matt skill can be a reference, as `codebase-design` is. `session` is an Addon despite its Matt contribution. Membership follows the Base upstream rows, the Utility list, and the Addon question keys, not a guess from a skill's name or description. Sources: [membership implementation](../../plugin/extensions/matt-skills.ts#L10-L28), [register Utility list](../../decision-register.yaml#L1029-L1045), [catalog loading](../../plugin/extensions/vstack.ts#L18-L27), and [artifact rules](../../README.md#L151-L153).

The counts were obtained by reading these local files and invoking the same `mattSkillNames` function that the extension uses. This read-only catalog query regenerates the counts and names from the repository root:

```sh
bun -e 'import {mattSkillNames} from "./plugin/extensions/matt-skills.ts"; const r=Bun.YAML.parse(await Bun.file("decision-register.yaml").text()); const p=Bun.YAML.parse(await Bun.file("pins.yaml").text()); const a=await Bun.file("addon-questions.json").json(); const names=[...new Bun.Glob("*/SKILL.md").scanSync({cwd:"plugin/skills"})].map(x=>x.split("/")[0]); const matt=[...mattSkillNames(r.items,k=>p.upstreams[k]?.role,Object.keys(a.questions))]; const utility=r.utility.map(x=>x.split("/").at(-1)); const addons=Object.keys(a.questions); console.log(JSON.stringify({shipped:names.length,matt:{count:matt.length,names:matt},utility:{count:utility.length,names:utility},addons:{count:addons.length,names:addons}},null,2));'
```

There was no existing `docs/research/` directory or research-note convention in `docs/`. The requested path is therefore `docs/research/flow-page-output-contracts.md`. Only this research document is written by this assignment. No tracker mutations, builds, tests, linters, formatters, or runtime smoke runs were performed.

## Terminology and design baseline

This document uses the settled names Flow page and Result block. On the research date, source files still said Grilling page and Report block. The current Result block shapes are `cards`, `ledger`, and `table`. The settled additions are Document, Comparison, Metrics, Code/diff, and Timeline. These eight kinds are design inputs, not shipped schema. The current schema also has Background, Topic, question visuals, and option previews. Sources: [record contracts](https://github.com/daandden/vstack/blob/7692b30904fff515f6b58901bb2a0456a7eb0e08/plugin/skills/grilling-page/SKILL.md#L39-L64).

The design brief also settles one Flow page for every flow, including standalone explanations, one Stage per result-producing run, Topics, a stages-only visual tree on `t`, newest-active-Stage priority on `n`, and an Overview progress strip. Existing nested-skill Stage rules differ from that target. Those differences need a cutover, not an assumption that current sources already implement the target.

The coverage tables use these labels:

- **Exact** means a current block has the output's required structure.
- **Flattened** means strings can preserve some content, but current blocks do not express the output's semantics or complete presentation.
- **Internal** means the skill supplies instructions or machine facts, not an independent human-facing result.
- **Gap** means the eight proposed kinds alone do not settle how the complete artifact is presented.

### Skill-creator evaluation details

These are different contracts, not one generic score:

- Behavior evals show each prompt, with-skill output, baseline output, assertions, user feedback, changed instructions, and unverified work. Sources: [eval review](../../plugin/skills/skill-creator/references/evaluation.md#L55-L88).
- Trigger evals write `commands.json`, `results.json`, and `scores.json`. Results cite session line numbers of successful loads. Scores distinguish all, train, and test trials, and exclude unfinished selection-only runs. The final comparison shows old and new descriptions and held-out results. Sources: [trigger output](../../plugin/skills/skill-creator/references/trigger-evals.md#L39-L51).
- Blind comparison reports randomized A/B outputs, per-criterion scores, winner or tie, evidence, and an unblinded causal analysis. Cost and variance can be material findings. Sources: [comparison contract](../../plugin/skills/skill-creator/references/blind-comparison.md#L21-L58).

Comparison and Metrics cover these if they retain trial identity, provenance, failure, and unverified states. An aggregate success percentage alone does not cover the contract.

## Command, tool, script, and agent outputs

### The one user Command

`/vstack-clean` is deterministic and model-free. It displays a dry-run table with repo key, kind, entry, age in days, size in bytes, total entries and bytes, and kept count. It offers Apply all, Choose items, and Cancel. Its checklist uses `ctx.ui.select` with checkbox options. It reports deleted count, freed bytes, skipped reasons, failures, and possible partial deletion. With no UI, it refuses through a visible custom message and `triggerTurn: false`. Table and ledger cover the result content. Integrating this Command into a Flow page is an ownership decision because it currently does not start a model turn or Matt run. A rendered cleanup result must not authorize deletion or replace its confirmation.

## Concrete gaps after the eight kinds

1. **Typed artifacts and media are still unspecified.** The current Visual union is text, HTML with scoped CSS, or SVG path. There is no raster-image, video, downloadable file, or executable-artifact record. Real examples are prototype screenshots, proof videos, exported PNG figures, raw traces, sqlite evidence, a questionnaire file, and a wizard script. This can be an attachment model shared by all Result kinds rather than a ninth Result kind. Sources: [Visual type](https://github.com/daandden/vstack/blob/7692b30904fff515f6b58901bb2a0456a7eb0e08/plugin/skills/grilling-page/scripts/grilling-page.ts#L24-L25), [prototype handback](../../plugin/skills/prototype/SKILL.md#L55-L63), [PR media](../../plugin/skills/open-pr/SKILL.md#L59-L64), [forensics paths](../../plugin/skills/forensics/SKILL.md#L78-L86).
2. **Interactive artifacts cannot be flattened without losing shipped behavior.** A logic prototype requires clickable actions and guided state walkthroughs. Teach requires quiz scripts and immediate feedback. Diagram-design optionally supports animation controls. The page rejects scripts, form elements, frames, and SVG animation. The product must choose a separate artifact route, a restricted embedded viewer, or supported server-owned widgets. None is implied by Document. Sources: [logic demo](../../plugin/skills/prototype/LOGIC.md#L35-L46), [lesson interaction](../../plugin/skills/teach/SKILL.md#L143-L155), [diagram motion](../../plugin/skills/diagram-design/SKILL.md#L374-L382), [blocked markup](https://github.com/daandden/vstack/blob/7692b30904fff515f6b58901bb2a0456a7eb0e08/plugin/skills/grilling-page/scripts/grilling-page.ts#L31-L55).
3. **No-result and incomplete-result states need representation.** The current renderer forbids empty reports, while code-review intentionally omits clean and skipped axes. Setup can stop before project configuration. ship can have a missing isolation notice or DRIFT, not a valid verdict. A human summary table can show each axis or step without fabricating cards. Sources: [review omissions](../../plugin/skills/code-review/SKILL.md#L128-L134), [setup non-Git branch](../../plugin/skills/setup-vstack/SKILL.md#L49-L51), [verifier availability](../../plugin/skills/ship/SKILL.md#L40-L50).
4. **Canonical artifacts and retention need a contract.** Flow folders expire together as Scratch. Specs and wayfinder tickets are canonical in the tracker. Teaching can retain durable pages. Research writes a repo file. All results on the Flow page does not settle whether the page copies content, renders referenced content, or holds an immutable snapshot plus canonical link. Sources: [Scratch retention](../../plugin/skills/vstack-tmp/SKILL.md#L9-L24), [map ownership](../../plugin/skills/wayfinder/SKILL.md#L19-L23), [research output](../../plugin/skills/research/SKILL.md#L10-L12), [teaching retention](../../plugin/skills/teach/SKILL.md#L147).
5. **Graph content differs from Stage navigation.** to-tickets and wayfinder have true blockers and parallel frontiers. `t` is settled as a tree of Stages only. Render the ticket graph as result content or a figure, without adding ticket nodes to that navigation tree. Sources: [ticket blockers](../../plugin/skills/to-tickets/SKILL.md#L39-L43), [wayfinder frontier](../../plugin/skills/wayfinder/SKILL.md#L65-L69).
6. **Generated images and security reviews are not missing shipped skill kinds.** There is no image-generation or dedicated security-review skill among the 76 shipped names. The shipped catalog does have diagram generation, security-related diagram patterns, proof screenshots, risk ledgers, and Blast radius review. A future image tool result needs the same media contract. A security finding can use cards plus evidence and a ledger without claiming a shipped security scanner or formal audit. Sources: catalog enumeration above, [security diagrams](../../plugin/skills/diagram-design/SKILL.md#L75-L82), [access matrix](../../plugin/skills/diagram-design/SKILL.md#L125), [safety finding contract](../../plugin/skills/blast-radius/SKILL.md#L57-L65).
7. **An arbitrary new skill cannot currently label a Stage.** The page requires registering its skill in `STAGE_LABELS`, despite many Utility results currently using their own pages. The replacement needs a rule for labels and identities when each result-producing run gets a Stage. Source: [current Stage contract](https://github.com/daandden/vstack/blob/7692b30904fff515f6b58901bb2a0456a7eb0e08/plugin/skills/grilling-page/SKILL.md#L40).

## Existing server, process, and session conventions

The shipped runtime is an ESM omp plugin with one registered extension. It imports `ExtensionAPI`, `ExtensionContext`, and judgment APIs from omp packages. There is no frontend application framework or HTTP dependency declared by the plugin manifest. Sources: [manifest](../../plugin/package.json#L1-L10), [extension imports](../../plugin/extensions/vstack.ts#L1-L11).

## Decisions still requiring user choice

The following choices change behavior or retention, rather than an implementation detail the codebase already settles:

1. Does the server only validate, render, and serve recorded facts, or does it also own workflow transitions? In either case, who records externally observed facts such as PR readiness and reached End state?
2. How are interactive lessons, logic demos, animated diagrams, and UI prototypes presented while the Flow page itself remains server-rendered structured data? Is opening a separate artifact acceptable, or must interaction happen inside the page?
3. Which results are copied into persistent Flow data, which reference canonical files or tracker objects, and which retain snapshots? How long does a Flow and its evidence remain after Scratch cleanup?
4. Does the all-results rule include triage's current discovery exception and the model-free `/vstack-clean` Command? If yes, which Flow owns a multi-item discovery or cross-repo cleanup result?
5. What state is durable across sessions and server restarts, and what closes or reopens a Flow? A finished result-producing Stage is not always a shipped change, a closed ticket, or a completed teaching mission.
6. What does the static fallback retain for interactive artifacts, linked media, and failed or partial results? Does it remain a self-contained offline page, or a readable summary with explicit unavailable interactions?

The eight agreed Result kinds cover the source-backed static report families. Typed attachments, executable-artifact presentation, provenance, and lifecycle authority remain the material design questions. They should not be disguised as additional standalone skills or solved by accepting agent-written HTML as the page format.
