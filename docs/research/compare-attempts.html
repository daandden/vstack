The vstack contracts of compare-attempts and blast-radius

This is the explainer for Specify the vstack contracts of compare-attempts and blast-radius, part of the map vstack: Matt Pocock skills plus pstack enhancements for omp. pstack arena becomes compare-attempts. Its runners now work in isolated omp clones on the parent's model, not in /tmp directories on three vendors' models. That change reshapes how candidates are written, picked, and judged, and it affects the two callers, blast-radius and architect. There are seven open questions, and each one ends with a recommendation. The pstack quotes come from the pinned text. The omp facts come from the oh-my-pi source (task/isolation-runner.ts, task/worktree.ts, eval/agent-bridge.ts).

Settled · pstack adoption

compare-attempts buys independence

arena is adapt as compare-attempts. Invoking it is the opt-in to Fan-out. Runners and the judge run on the parent model in fresh contexts, and the skill must say that this buys independence, not model diversity.

Settled · roster + ADR 0007

Runners are isolated workers

Runners are vstack-worker agents spawned through eval agent(..., isolated=True, apply=False, merge=False). The parent applies only the candidate it picks, from that candidate's patchPath. The cross-judge is a vstack-explorer. If isolation is off, the skill stops and never falls back to the shared checkout.

Settled · overlap ticket

Only on explicit ask

architect's Sketch uses DESIGN-IT-TWICE and switches to compare-attempts only when the user explicitly asks. Step 6 of blast-radius is the same. The Safety reviewer in code-review runs blast-radius with "skip step 6".

The skill at a glance

pstack's six phases stay. Each one below is marked with what vstack changes and the question that settles it.

Coral phases change shape in vstack. White phases keep pstack's logic and get only House-style wording.

Q1Gate and inline line

Every path into compare-attempts is an explicit user request. The user types /skill:compare-attempts, or asks architect or blast-radius for it in words. Under the shared rubric (skill://vstack-fan-out), check 1 is "the user's words decide", so the invocation itself counts as "fan out". The judge never decides here. Two cases still reach the inline line: the user also said "sequential" or "no fan-out", or the agent cannot spawn. The question is what inline means for this skill.

With A, "sequential" stays meaningful: each attempt still gets its own context and clone, and only the parallelism goes away.

Q3Where candidates are written

pstack writes each candidate to "a git worktree where possible, otherwise /tmp/arena-<slug>/candidate-<n>/" (arena SKILL.md:29). In vstack the omp clone is the per-candidate location. The omp source confirms four facts:

  • The patch is the delta against the parent's tree at spawn, and it includes the parent's uncommitted state (task/worktree.ts, baseline capture).
  • It includes new files that are not gitignored. Gitignored files are not captured.
  • With apply=False, the patch stays at <artifacts dir>/<agentId>.patch, and the eval result returns it as patchPath (isolation-runner.ts:272).
  • Writes through the vstack root bypass the clone. They are immediate and are not in the patch (ADR 0007).

Option A (coral): the clone holds the candidate, the patch carries it out, and Pick applies exactly one. Option B (grey dotted): candidates written through the vstack root land in the parent's live checkout in Standard mode.

A · Real target path in the clone (recommended)

The patch is the candidate, and picking means applying it. The same rule works for code, docs, and type sketches. The vstack root is still passed down, but only for nested writers such as research's background agent, never for the candidate itself.

B · Per-candidate directory under the vstack root

<vstack root>/artifacts/compare-attempts/<slug>/candidate-<n>/. It survives the session. But in Standard mode, the vstack root is the main checkout, so runners write straight into the parent's tree and Pick has nothing to apply.

Recommendation: A.

Q4Pick, apply, and what happens to the rest

The caller declares one of two artifact kinds. With tree, the candidate is a working-tree change, and the parent applies one patch. With reply, the candidate is a written answer, and the patches are evidence only.

The coral path is kind tree (the default, used by architect). The grey path is kind reply (used by blast-radius, Q6).

Q5The cross-judge on the parent model

Choose one model from the arena cross-judge pool line … Prefer a different model family from the parent's. Spawn one readonly judge subagent on that model. … It runs in parallel with the parent's reading in Phase D, not with the candidates themselves. (arena SKILL.md:41)

With a single model, the judge's only value is its context: it wrote no candidate and has not seen the parent's scores. The timing stays the same as in pstack.

The judge is a single spawn via task. It is not isolated because it is read-only. Runner ids are hidden behind labels. If it cannot be spawned, it is skipped, and the note says "cross-judge: not run". A judge run inline in the parent would judge nothing independently.

Draft text for the skill

The cross-judge runs on your model. It buys a context that wrote no
candidate and hasn't seen your scores: independence, not a second
model's taste. Agreement means the rubric reads one way; it does not
rule out a blind spot you both share.

The same honesty applies elsewhere. The skill intro and blast-radius step 6 drop "Different models catch different real bugs".

Q7architect's Sketch with compare-attempts

Run the arena skill with the design-sketch task and the Phase A grounding artifacts. Pass references/runner-prompt.md as each runner's prompt. (architect SKILL.md:31)

In vstack, Sketch defaults to DESIGN-IT-TWICE, as decided on the overlap ticket. compare-attempts replaces it only when the user explicitly asks. The two modes differ in who designs, and in where each design lives.

Both modes produce the same design package, so Stop, Implement, and Scrap don't change. The dashed arrow is the Scrap loop, which returns to the same Sketch mode.

design-brief.md: the opening paragraph becomes neutral

The brief now serves two kinds of reader. DESIGN-IT-TWICE explorers reply in text, and compare-attempts workers write files in their own tree. So the brief stops saying where output goes, and the caller says it instead.
