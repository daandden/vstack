How pstack principles reach the agent

Explainer for “Decide how pstack principles are delivered” (#33). Everything here is already settled except Q1: reach, which is the choice between the three options below.

Already decided

Background: two facts that shape the choice

1. What omp puts in the system prompt

  • A visible skill shows up as one line in the skill list, and omp's smol model rewrites that line to at most 12 words.
  • A hidden skill (disable-model-invocation: true) shows up nowhere in the prompt, but the agent can still read it through skill://name.
  • An always-apply rule is copied into the prompt word for word, on every turn.
  • Skill bodies never sit in the prompt. The agent reads a body only when it decides to.

2. How pstack itself does it

  • All 23 principles are hidden skills.
  • Workflows cite principles at specific steps. For example, architect says “Design it twice … the exhaust-the-design-space principle skill made concrete.”
  • The only index of all principles lives inside poteto-mode, so it loads only when that mode is on.
  • In practice, then, pstack is citations only, plus an opt-in index.

A citation: what the agent actually sees

A citation is a pointer placed inside a skill step. Nothing about the principle is in the prompt until the agent reaches that step.

## diagnosing-bugs (vstack version, excerpt)

3. Reproduce the failure before changing code.
4. Trace the symptom to its root cause and fix it there
   (read `skill://principle-fix-root-causes`).
5. ...
User: “this test is failing, debug it”→ agent loads diagnosing-bugs→ reaches step 4→ reads principle-fix-root-causes
User: “rename this variable”→ no skill runs→ principle never loaded

The three options

recommended

1. Citations only

Same as pstack without poteto-mode.

<system prompt>
… no principle text at all …
<skills list>
diagnosing-bugs: …
tdd: …
(principles hidden)

Loads when: a running skill reaches a step with a skill://principle-… pointer, or you type /skill:principle-….

  • Nothing is always on, so it costs 0 tokens per turn.
  • A vague principle only fires at the exact step that cites it.
  • No clash with omp's own harness rules, such as its rules on verification, root causes, and asking.
  • Plain sessions with no skill running never use principles.
  • A principle helps only where some skill cites it.
middle

2. Citations + small always-on index

Only principles the harness doesn't already cover.

<generic-rules> vstack-principles
- Replacing an internal API → migrate every caller … skill://principle-migrate-callers-…
- Command that can crash or retry → converge … skill://principle-make-operations-idempotent
- … (a handful)

Loads when: at a citation, as in option 1, or when a line in the index matches the work, in any session.

  • A few distinctive principles reach every session.
  • Small cost, a few hundred tokens at most.
  • Someone has to judge which principles overlap the harness, and re-judge at every Update.
  • One more thing to install: a rules path next to the skills.
max reach

3. Citations + full always-on index

Prototype option A: all 23 lines.

<generic-rules> vstack-principles
- Sizing a diff … → delete first … skill://principle-laziness-protocol
- Before writing logic → pick core types …
- About to declare done → exercise the real artifact …
- … 23 lines, about 860 tokens

Loads when: any index line matches, in any session.

  • Every principle reaches every session.
  • Broad triggers such as “any non-trivial work” and “before writing logic” fire all the time, causing needless reads.
  • Many lines repeat omp's harness rules, which states the same rule twice and risks the two versions drifting into conflict.
  • About 860 tokens on every turn.
