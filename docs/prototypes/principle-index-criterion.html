Which principles go in the always-on index?

Explainer for Q5 of “Decide how pstack principles are delivered” (#33). Decided so far: citations plus a small always-on index, where #32 decides membership, the rule file records it, vstack writes each line, and one always-apply rule carries the index. The open question is the test #32 uses to decide which principles earn an index line.

Why a test is needed at all

Broad triggers fire all the time

Some pstack triggers describe nearly every coding turn:

  • build-the-lever: “Apply to any non-trivial work”
  • foundational-thinking: “Apply before writing logic”
  • type-system-discipline: “…or writing code in any statically-typed language”

Always on, these cause a skill read on almost every turn. That's the “unnecessary calling” worry.

Some principles repeat the harness

The omp system prompt on this machine already says, for example:

  • “NEVER yield without a smoke run … Tests alone are not proof.” → prove-it-works
  • “Default clean cutover: migrate every caller … no shims.” → migrate-callers-…, outcome-oriented-execution
  • “Bug: reproduce before; confirm after.” / “NEVER solve symptom” → fix-root-causes

Listing these as well states the same rule twice, and the two copies can drift into a conflict.

The recommended test: two gates

Gate 1: Specific?
Does the trigger name a situation you can observe, one that happens in some turns and not others? For example, “two fixes sharing one premise failed the same gate” passes; “any non-trivial work” fails.
Gate 2: Not covered?
Is the rule absent from omp's harness prompt and from vstack's own always-apply rules? If the harness already says it, the index adds only duplication.
Both pass → index line.
A principle that fails either gate is still adopted if #32 says so. It is just reached through citations only.

The three options for Q5

recommended

Specific + not covered

Both gates must pass.

  • Smallest index, about 10 lines.
  • No broad triggers firing every turn.
  • No duplication of the harness.
  • It's a written test, so each Update can re-check against it.
  • Principles such as build-the-lever never reach plain sessions.

Not covered only

Only Gate 2 applies.

  • Also indexes build-the-lever, foundational-thinking, type-system-discipline, and sequence-verifiable-units.
  • Those broad triggers fire on nearly every turn, which is exactly the unnecessary calling you were worried about.

Hand-picked, no test

You pick members by taste.

  • Quick, and fully in your control.
  • Each Update has no rule for judging whether a new or changed principle belongs.

One caveat for any option

Gate 2 compares principles against omp's harness prompt, but omp isn't an Upstream and has no Pin. If a new omp version drops a rule, such as the smoke-run rule, a principle that was “covered” silently stops being covered. It's worth deciding whether the Update process re-runs Gate 2 against the current omp prompt.
