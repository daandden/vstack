# Shared judge text goes in the jev state once

> [ADR 0025](0025-subagents-get-principle-picks-from-their-own-brief.md) amends this decision. The check flags an unexpected, non-allowed pick over 0.85, not 0.80, in `sample-prompts.json` and `sample-briefs.json`. Scores from 0.65 through 0.85 are borderline.

TypeSafe jev (`POST /v1/systemone`) bills input tokens only, at $0.042 per million. It reads the `state` once per request and answers every question in that request, so text repeated in every question is billed once per question, and text in the state is billed once. The Addon judge therefore moves its shared preamble out of all 35 questions and into the state, and the Grilling page visual judge moves diagram-design's 45-row visual-type guide out of its two type questions and into the state. The extension also leaves out every Addon already delivered in the session before it sends the request, instead of dropping it after the answer. The new state put two expected picks under the 0.75 selection threshold, so the threshold moves to 0.70. We chose the lower input cost over the calibration that the old shapes had, and we recalibrated both judges against their corpora before the move shipped.

## Considered Options

- Keep the shared text in every question. This needs no recalibration. But each Addon request pays for the preamble 35 times, and each visual request pays for the guide twice.
- Put the `preamble` field before `request` in the Addon state. In five wordings, `restated-upstream-bump` scored `vstack-maintain` at 0.580 to 0.667, under the 0.70 selection threshold. With `request` first, the same probes scored it at 0.70 to 0.735.
- Keep the 0.75 selection threshold. With the new state, 2 of 104 expected picks then score under it, and the runtime does not select them.
- Drop delivered Addons after the answer, as the extension did before. jev then scores questions whose answers the extension cannot use.
- Build the visual check's request in TypeScript from the rubric. The helper is Python, so two builders could drift.
- Keep the visual check as a Bun CLI that runs the helper through `python3`. That needs a second Python outside eval's interpreter, and the CLI calls the REST API instead of `judge_batch`, which the helper calls.

## Consequences

- `addon-questions.json` is `{ "preamble": ..., "questions": { <addon name>: question } }`. Each question keeps only its situation and its criteria. `plugin/extensions/addon-catalog.ts` parses the file once into a typed value for the extension, `scripts/addon-judge-check.ts`, and check-register. It also builds the state, `{ request, preamble }`, with `request` first.
- The shipped preamble is: "The state's `request` is a user's request to a coding agent. Judge the inherent task, not its phrasing. Answer yes only if the task clearly falls into the situation in the question. If torn, answer no."
- In measured input cost, 12 sample prompts went from 63,214 to 45,814 input tokens (-27.5%), with 2 picks flipped before tuning. The whole corpus, one request per prompt, went from 690,510 to 500,691 tokens (-27.5%). The 75 visual cases went from 232,373 to 190,598 tokens (-18.0%). The guide is about 3,500 characters.
- The Addon recalibration ran on jev-1.13.0, with 3 runs per prompt. Before the move, 131/131 prompts passed with 0 flags and 53 borderline. After it, at the 0.75 threshold, 131/131 passed with 0 flags and 49 borderline, but `principle-encode-lessons-in-structure` on `g-graphql-codegen` scored 0.733 and `vstack-maintain` on `restated-upstream-bump` scored 0.737.
- The selection threshold is 0.70, in the extension and in `sample-prompts.json`. The check flags an expected pick under 0.65 and an unexpected, non-allowed pick over 0.80, and scores from 0.65 through 0.80 are borderline. With fresh baselines at 0.70, 131/131 prompts passed with 0 flags and 70 borderline. All 104 expected picks scored 0.70 or more (the lowest at 0.717). 16 unexpected, non-allowed picks scored 0.70 or more, against 3 at 0.75, and none scored over 0.80. `sample-prompts.json` holds these baselines and the state shape. A later change to the preamble, the state shape, or the threshold needs fresh baselines.
- In the visual recalibration, the type questions keep only the type names, with a null rubric, and the state holds `question` and `visual_types`. The live four-question request passed 75 of 75 cases with the guide in the type questions, and 75 of 75 with the guide in the state.
- `scripts/visual_judge_check.py` runs in omp's Python eval. It builds every request with `judge_request()` in `visual_judge.py` and sends all cases through `judge_batch`, as the helper does. It refuses to grade unless `judge_batch` used a TypeSafe jev model, because without TypeSafe credentials `judge_batch` can resolve to another model. A type case passes when its type is in the top three of either type question.
- Delivered Addons stay the same. When every Addon was delivered earlier in the session, the extension sends no request and calls no smol.
- This amends ADR 0002. The shared judging text is in the state, not in each question, the request leaves out delivered Addons, and the selection threshold is 0.70. It also amends ADR 0018, whose threshold is now 0.70. In ADR 0018 and ADR 0021, the judge input is now the `request` field beside the preamble. In ADR 0019, the catalog key is now a key in the `questions` map.
