# Isolated subagents run unapplied and write artifacts through the vstack root

Five subagent roles need their own checkout: hillclimb hypothesis workers, compare-attempts runners, wayfinder research runners, ship verifiers, and the background babysitter. Each one runs under omp's own task isolation (the APFS clone on macOS). It is spawned with eval `agent(..., isolated=True, apply=False, merge=False)`, so the parent applies only the candidate it picks, from that candidate's `patchPath`. `merge=False` forces patch mode. Without it, the call inherits the machine's `task.isolation.merge`, and in branch mode omp returns a `branchName` instead of a `patchPath`. omp clones `.git` into each isolated workspace and merges back only working-tree changes. A Private-mode artifact written under a recomputed `--git-common-dir` would therefore land in a disposable copy. To prevent that, the top-level agent resolves the **vstack root** once, and every spawn prompt carries it as an absolute path. Children write vstack config and artifacts only under that root, and they pass it on to their own children. We chose this so the user keeps APFS isolation, and Private-mode artifacts survive at any depth.

## Considered Options

- **`tasks[]` with `task.isolation.apply: false` set machine-wide by setup-vstack**: rejected. It keeps one batch form, but it changes how every non-vstack isolated task behaves on the machine.
- **Children never write Private artifacts; they return content, and the top-level agent writes it**: rejected. A nested writer, such as research's background agent under a research runner, would have to route its content back through every level.
- **The parent runs `git worktree add`, which shares `.git` the way `/wt` does**: rejected. Artifacts would persist with no extra rule, but this gives up APFS speed and the carried-over dirty state. The user prefers omp's isolation.
- **omp `isolated: true` through `tasks[]` with apply on**: rejected. Auto-apply conflicts with keep-only-the-best (hillclimb, compare-attempts), and it would merge a verifier's or a babysitter's checkout state back into the parent.

## Consequences

- A Fan-out line's batch may be one eval `agent()` batch as well as one `tasks[]` batch. The lint in `check-register.ts` accepts both forms, and every spawn site still names a vstack agent.
- setup-vstack gains a seventh machine check: `task.isolation.enabled` is on, and it is set only with approval. A skill that needs an isolated role while isolation is off stops and points at setup-vstack. It never falls back to the shared checkout.
- The vstack Private-mode rule gains one line: a subagent uses the vstack root from its prompt and never re-resolves `--git-common-dir`.
- omp isolation is not a filesystem sandbox. Writes through the vstack root are immediate, and the patch does not cover them. Children write disjoint files under it.
- In Standard mode, the vstack root is the user's main checkout. An isolated child's artifact that belongs on a throwaway branch, such as a wayfinder research runner's findings file, is therefore written inside the child's own clone and travels in its patch. The parent lands that patch on the branch through a temporary worktree. Writing it through the vstack root would dirty the user's checkout.
- One exception: **Scratch** (see [Decide where vstack keeps scratch artifacts under ~/.vstack and how they are cleaned up](https://github.com/daandden/vstack/issues/57)). The top-level agent resolves the project's absolute Scratch dir once (`~/.vstack/tmp/<repo-key>/`, from `skill://vstack-tmp`'s `scripts/path.ts` run with no argument) and passes it in the spawn prompt, as it does the vstack root. It never passes a `<kind>/` dir; a child appends its own kind (`<Scratch dir>/<kind>/…`) and never runs `path.ts` itself. A child, isolated or not, may write Scratch only under that directory. That includes the decision-trail log, which now lives at `<Scratch dir>/decision-trail/<task-slug>-<session-uuid8>.tsv` in both modes; children append to it only through `scripts/log.sh`. These are the only writes a child may make outside the vstack root and its own clone. They go to the real files, not to a clone's copy. (This replaces the earlier exception for a Standard-mode decision-trail log in a linked worktree's work dir, from [Specify the vstack contracts of session-lessons and decision-trail](https://github.com/daandden/vstack/issues/51#issuecomment-6034998264).)
- Amended by the Hand edit isolated-maintain-forensics: two more roles run isolated, vstack-maintain's drafting worker and forensics' live-run worker. The drafting worker drafts a vstack change and runs `prepare` and `gates` in its own clone. A change that passed `gates` there can land in the checkout that the installed plugin loads, because the old worktree rule only kept half-written text away from other sessions. The live-run worker holds the app and every probe, and its patch is never applied. Both skills stop when isolation is off.
- Amended by the Hand edit remove-decision-trail. The decision-trail log and its Scratch exception are removed. hillclimb's parent writes its attempt log under its own `hillclimb` kind, and no child writes Scratch outside its own kind dir.
- Amended by the Hand edit verifier-shared-checkout. Every verifier call uses isolated eval arguments. Before mutation, the verifier proves its Isolated clone through omp's system Working Tree notice and a canonical Shared checkout path guard. It runs in a separate detached head worktree, removes nonignored untracked inputs while preserving ignored inputs and the Shared checkout's exclusions, and attempts worktree removal on every exit. Failed isolation or head preparation returns REFUSED, never an app finding or Drift. A removal failure preserves the actual verdict and evidence and adds an optional nonempty `cleanup_error` string. ship reports that error separately and treats the run as UNAVAILABLE, even when the app verdict is PASS or PASS+NOTES.
- Amended by [ADR 0043](0043-an-independent-verifier-owns-final-proof-at-every-end-state.md). The ship Verifiers become final Verifiers: implement's shared End state block starts one at every End state, commit included, and ship reuses its protocol. Every Verifier runs the head SHA in a separate detached worktree, even when its Isolated clone is clean, and leaves its baseline untouched. END-STATE step 6b owns the shared brief, record validation, and unavailable-proof handling above.
- Amended by #323. The parent owns each Isolated clone through `plugin/skills/vstack-fan-out/WORKER-LIFECYCLE.md`, including failures, superseded attempts, and early stops. Running or still-needed workers stay retained with reasons. The parent preserves useful unapplied work and evidence outside the clone before releasing its own settled child through omp's supported lifecycle operation, then checks disk and listing disappearance. Parking does not reclaim a clone. This release is separate from a Verifier's detached head worktree cleanup and does not change user `/wt` or temporary Git worktree ownership.
- Amended by [ADR 0059](0059-vstack-requires-ovnfs-for-isolated-work-and-its-own-checkouts.md). Isolated roles run in ovnfs checkouts instead of the APFS clone, and vstack requires ovnfs. The Verifier's detached head tree becomes an ovnfs checkout at the head commit, made through vstack-worktree.
