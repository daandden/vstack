# Private MCP config uses shared storage and a named checkout hook

Private mode setup keeps the native project MCP configuration in the Git common directory and puts absolute symlinks in the main checkout and future worktrees. It reconciles the main and shared configurations before replacing the main file, preserves every nonconflicting server and setting, requires explicit choices for conflicting values, and retains recoverable originals. Existing worktrees are outside this migration. This extends the shared-storage decision in [ADR 0006](0006-vstack-owns-its-project-config-paths.md) and follows the absolute-link precedent in [ADR 0009](0009-private-verify-skill-lives-under-the-vstack-root.md).

A repository-local named configuration hook handles eligible new worktrees. Setup requires configuration-hook support in the Git selected by the worktree creator, available upstream from Git 2.54. It leaves the existing hook directory, `core.hooksPath`, and unrelated hook definitions unchanged. Unsupported Git leaves this MCP setup explicitly incomplete. We reject a legacy hook wrapper because it would replace an occupied hook entry and require maintaining its dispatch behavior. Outside an explicitly selected reconciliation, the hook preserves and refuses a regular config or a link to another target.

Private MCP setup may add its link's exclusion to the repository-local `info/exclude` in the Git common directory. It preserves unrelated entries and changes no tracked ignore file or global Git setting. This is a narrow exception to setup-vstack's existing no-ignore-file-write rule, following ADR 0009's private Verify-link precedent. Requiring an existing exclusion would leave fresh repositories incomplete and could leave an untracked link eligible for ordinary staging.

Users edit the canonical shared JSON file directly and then run `/mcp reload`. Native project-scoped MCP mutation commands are outside the sharing guarantee. The inspected omp 18.18.8 writer renames a temporary regular file onto the supplied config path without resolving its symlink, so those mutations can replace the link. Fixing that writer or its locking requires external omp work and is not part of this change.

The maintainer selected these constraints during [issue #460](https://github.com/daandden/vstack/issues/460)'s grill and the nested exclusion-policy question. The choices trade older-Git compatibility and native mutation convenience for preserving existing hooks and keeping this change within vstack. Standard mode, user-level MCP settings, and machine-wide Git selection remain unchanged.
